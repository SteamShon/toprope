# 2026-11-04 Toprope 정의 합의

## 한 문단
Toprope는 조직에서 사람들 사이에 숨어 있는 워크플로우를, 사람과 에이전트가 함께 쓰는 도메인 모델로 바꾸고, 그 모델이 쓰이는 동안 계속 나아지게 하는 가볍고 열린 기반이다.

## 왜
개인 생산성은 올랐는데 조직 생산성은 오르지 않았다. 코드를 제품에 반영하거나 실험으로 지표를 바꾸는 사람 간 워크플로우가 암묵적이고 구전으로만 전해진다. 그래서 에이전트가 자동화할 수 없고, 결정이 쌓이지 않아 학습도 할 수 없다.

## 합의 내용
- 워크플로우 = 도메인 (Object, Link, Action). 하나의 모델에서 MCP(에이전트)와 UI(사람)를 생성한다.
- 저자: 현업, 개발자, 에이전트 모두. 에이전트가 초안을 쓰고 사람이 결정한다.
- 정체: 저작 도구(팩토리) + 실행 경로 + 기존 시스템 위의 층
- 쌓이는 결정: 업무 수행 결정과 도메인 변경 결정, 같은 무게
- 원재료 순서: 기존 시스템 → 기존 기록 → 인터뷰 → 써보며 개선
- Foundry와의 차이: 저작 비용, 에이전트가 1급 사용자, 운영하며 진화, 가볍고 열림
- 첫 도메인은 Toprope 자신(self-compile). 이후 다른 도메인을 dogfooding한다.

## 주장 사슬 = 프로젝트의 기준
① 만들 수 있다 → ② 모델이 맞다 → ③ 같은 언어 → ④ 진화 → ⑤ 조직 생산성

| 마일스톤 | 고리 |
|---|---|
| M0 | 주장 없음 (커널) |
| M1 | ①② self-compile |
| M2 | ①② dogfood 재현 (실험 수명주기 후보) |
| M3 | ③ |
| M4 | ④ (self 도메인 포함, 자기 승인 금지) |
| M5 | ⑤ 일부 + 공개 |

## 미결
- 구현 언어 (제안: TypeScript core + Python 분석)
- "오픈 UI"가 특정 라이브러리나 스펙을 뜻했는지
- M2 원천 시스템 (GrowthBook 가능 여부)
- M1 정답지 시나리오 약 30개는 연구자가 직접 작성하고, 초안 전에 동결
