# 관련 연구 메모: Palantir AIP Boardroom (beta)

Link: ⑥ (포지셔닝), ① (아이디어 후보). 출처: Palantir 문서 "AI Platform (AIP) / Boardroom / Overview"
(연구자가 2026-11-04에 공유한 본문). 원문 링크의 Threads 글은 확인하지 않았음.

## 요약
- director 에이전트 + 분야별 전문가 에이전트 팀이 Ontology를 검색·조회하고, 코드 실행,
  분석, 시각화, 문서·슬라이드 생성을 함께 함. 텍스트 또는 음성으로 협업.
- 에이전트마다 지시문, 모델, 도구, 컨텍스트를 설정. memories와 재사용 skills.
- 세션과 생성물은 Ontology에 저장되어 "누적되는 데이터 자산"이 됨. 접근은 객체 보안 정책.
- 모드: Chat, Panel(실시간 회의, 받아쓰기), Documents(인용 포함 문서), Slide decks,
  Plans(한 팀이 계획을 만들고 다른 팀이 비평하며 개선).

## Toprope와 같은 방향
- 에이전트가 Ontology(선언된 도메인) 위에서 일한다.
- 작업 기록이 다시 Ontology에 쌓여 자산이 된다 → Toprope의 이벤트 소싱과 결정 기록,
  주장 ⑤(도메인이 진화한다).
- 객체 단위 접근 통제 → ADR-0016.

## Toprope만의 자리 (포지셔닝)
Boardroom 문서는 에이전트가 **무엇을 할 수 있는가**(도구, 권한, 기억)를 다루고, 업무
규칙이 **맞는가**는 다루지 않는다.
- 어떤 단계에서 어떤 행동이 허용되는가 (전이 매트릭스)
- 어떤 경로로도 깨지면 안 되는 것 (불변식)
- 생성된 도구가 선언대로 동작하는지 (하네스)
- 에이전트는 제안, 사람이 확정

"에이전트에게 Ontology를 주면 일을 한다. 그 일이 조직의 규칙을 지키는지는 누가
보장하나?" → Toprope의 정확성 계층. 공개 전 README 포지셔닝 후보 문장.

## 가져올 만한 아이디어 (M2 이후 제안 후보, M1 arm은 고정)
1. director + 전문가 에이전트, Plans 모드의 "다른 팀이 비평": Phase A 인터뷰에서 영역별
   에이전트가 초안을 쓰고 다른 에이전트가 충돌을 찾는 구조.
2. Panel 모드(음성 + 받아쓰기): 전문가 인터뷰를 말로 하고 받아쓴 내용을 인터뷰 로그나
   소스로 사용. 소스 리더는 이미 transcripts를 받음.
3. skills와 memories: 여러 도메인에 걸쳐 확인된 인터뷰 기본값(ADR-0014)을 다음 도메인에
   제안.
